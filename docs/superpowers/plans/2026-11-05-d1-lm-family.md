# d1-2B Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Load, answer, read, edit, check and save d1-2B with our own PyTorch and MLX code, as a third decision-model family.

**Architecture:** Each family moves into its own folder under `dspy_wsp/decision/families/`, with a registry that `loading.py` reads. The new family `d1_lm` has three parts: an encoding module in Python and NumPy (token ids, attention masks, answer positions, readout tokens and calibration), an LFM3 backbone in each framework, and a network that runs the backbone and scores option tokens at the answer positions. The backend gains request-level encoding, so one row can answer several questions.

**Tech Stack:** Python 3.12, PyTorch, MLX, `tokenizers`, safetensors, pytest.

**Spec:** `docs/superpowers/specs/2026-11-05-d1-lm-family-design.md`

## Global Constraints

- The pinned model is `LiquidAI/d1-2B` at revision `652f920e544ea37f81e4b0ce89b81d4ed0da90b1`, under the LFM Open License v1.0.
- Runtime code never imports Liquid's code or uses `trust_remote_code`. Only the opt-in reference tests (`WSP_REFERENCE_TESTS=1`) do.
- Module names equal checkpoint tensor names. The language model's tensors start with `model.language_model.`.
- The network runs in float32.
- `set_size` is 16. The answer lead is `<think></think>`. The BOS string is `<|startoftext|>`. No system turn is written.
- The temperature is the default in `calibration.json` (1.337 at the pinned revision).
- Choice, Noul and Score only. Any other type, and `multiple: true`, raises `RequestError`. Text states only.
- Protected tensors are `model.language_model.embed_tokens.weight` and `model.language_model.embedding_norm.weight`.
- Every local run on the real model needs the user's confirmation first. Unit tests on the tiny fixtures need none.
- Comments are short and describe the code in its own file. Markdown never refers to conversations.

## Review Focus

1. **A request with more than 16 questions.** It splits into groups of 16 in request order, and every question gets an answer. Test it in Task 3, and through the backend in Task 7.
2. **A state that contains `<|im_end|>` or `QUESTION:`.** The special token is broken with a zero-width space, the turn does not end early, and the answers are valid. Test it in Task 3.
3. **A Choice whose keys are already single letters, e.g. `{"B": ..., "A": ...}`.** The keys themselves are the codes, in key order. Test it in Task 3.
4. **Two requests of different lengths in one batch.** Right padding changes no answer, so a request's answers alone and in a batch match within 1e-5. Test it in Tasks 5, 6 and 7.
5. **A Noul with criteria.** The prompt includes `Yes:` and `No:` lines, and the answer's `true` probability is P(yes). Test it in Tasks 3 and 7.

### Task 2: Requests as the unit of encoding

**Interfaces:**
- `DecisionBackend._encode_request(state, questions: dict[str, Question]) -> list[tuple[Row, list[str]]]` returns each row with the names of the questions it answers, in order. The default is `[(self._encode(state, q), [name]) for name, q in questions.items()]`.
- `DecisionBackend._row_outputs(output, n: int) -> list`: given the network's output for one row (from `logits` or `capture`), it returns one item per question of that row. The default is `[output]`.
- `_decide` and `read` call these two hooks. `_row_tokens(row)` keeps counting each row's tokens once.
- `read` returns rows in the order of the request's questions, whatever the packing.

### Task 3: d1-2B encoding

**Files:**
- Create: `src/dspy_wsp/decision/families/d1_lm/__init__.py`, `encoding.py`
- Modify: `tests/decision_fixtures.py`, to add `build_d1_lm_tokenizer(folder)` and `d1_lm_config(vocab)`

**Interfaces:**
- `Tokenizer(folder)` wraps `tokenizer.json` and `tokenizer_config.json`. It provides:
  - `encode(text) -> list[int]` with `add_special_tokens=False`;
  - `bos: str`;
  - `pad_token_id: int`;
  - `specials: list[str]`, the special tokens longer than one character, longest first.
- `plain(tok, text) -> str` breaks special-token strings with `"​"` after their first character. It repeats until nothing matches, as Liquid's `_plain` does.
- `state_block(state) -> str` returns a string state followed by `"\n\n"`, or `json.dumps(state, ensure_ascii=False, indent=2) + "\n\n"`.
- `option_codes(keys, scheme=2) -> list[str]` and `code_tokens(tok, keys, scheme) -> list[tuple[str, int]]` follow Liquid's `option_codes`, `_FALLBACK_POOL` and `_aliases_cached`.
- `readout_groups(tok, q: Question) -> list[list[int]]` returns one group per option in `q.option_keys` order:
  - Noul gives `[no forms, yes forms]`, already reordered to our `[false, true]`.
  - Score gives the digits.
  - Choice gives the code token followed by the `" {code}"` token when that is a single token.
- `question_block(tok, q) -> str` and `suffix(tok, q) -> str` follow the spec's layout. The suffix ends with `<|im_end|>\n<|im_start|>assistant\n<think></think>`.
- `@dataclass Row` has these fields:
  - `ids: list[int]`
  - `state_len: int`
  - `question_of: list[int]`, holding -1 on the state and 1..N on question tokens
  - `slots: list[int]`, one answer position per question
  - `questions: list[Question]`
- `encode_request(tok, state, questions: list[Question], set_size=16, max_length: int) -> list[Row]` follows Liquid's `_sequences` and `pack_set`:
  - The first group's ids are `encode(prefix + suffix_1)`.
  - `state_len` is `len(ids) - len(encode(suffix_1))`.
  - Each further question appends `encode("QUESTION:\n" + suffix_k)`.
  - Each slot is the last index of its question.
  - A row longer than `max_length` raises `RequestError`.
- `prefix(tok, state) -> str` returns `f"{tok.bos}<|im_start|>user\n{plain(tok, state_block(state))}\nQUESTION:\n"`.
- `probabilities(scores: np.ndarray, temperature: float) -> list[float]` is a softmax of `scores / temperature`.
- `load_calibration(folder) -> float` reads `calibration.json`'s `"default"`, or returns 1.0 when the file is absent.
- An unsupported type raises `RequestError("d1-2B in dspy-wsp answers choice, noul and score questions")`.
- `parse_question` passes extra keys through only if it already keeps them. Reject `multiple` in `encode_request` by checking the raw request in the backend in Task 7, and also here if `Question` exposes it.

### Task 5: LFM3 in PyTorch, and the d1-2B network

**Files:**
- Create: `src/dspy_wsp/decision/families/d1_lm/lfm3_torch.py`, `torch.py`
- Modify: `tests/decision_fixtures.py`, to add `build_d1_lm(folder) -> Path`
- Test: `tests/test_d1_lm_network.py`

**Interfaces:**
- `lfm3_torch.LanguageModel(text_config: dict)` has the modules `embed_tokens`, `layers.{i}` and `embedding_norm`. Each layer has `operator_norm`, `ffn_norm`, `post_operator_norm` and `post_ffn_norm` (when `use_sandwich_norm`), and `feed_forward.{w1,w2,w3}`. A conv layer also has `conv.{in_proj, conv, out_proj}`. An attention layer also has `self_attn.{q_proj, k_proj, v_proj, o_proj, q_norm, k_norm, gate_proj}`.
- `forward(ids [B,T] long, full [B,T,T] bool, sliding [B,T,T] bool, real [B,T] bool, layers: list[int] = ()) -> tuple[Tensor, dict[int, Tensor]]` returns the final normed hidden state and the hidden state after each requested layer (0 means the embeddings).
- The computation follows Liquid's `modeling_lfm3.py`:
  - RMSNorm in float32.
  - Rotary embeddings per layer type, with frequencies from `rope_parameters[type]`. Partial RoPE keeps the full-dimension frequency progression for the first `int(factor * head_dim) // 2` frequencies and sets the rest to zero.
  - Queries and keys are RMS-normed per head before RoPE.
  - Attention is followed by a per-head sigmoid gate from `gate_proj(x)`.
  - The short convolution: zero the padded positions, `B, C, x = in_proj(h).chunk(3)`, `y = B * x`, zero the padding again, causal depthwise conv of width `conv_L_cache`, then `out_proj(C * y)`.
  - Each block applies `h = h + post_op(op(operator_norm(h)))`, then `h = h + post_ffn(ffn(ffn_norm(h)))`.
  - Positions are `arange(T)`.
- `torch.D1LMTorch(config: dict)` has `self.model.language_model = LanguageModel(config["text_config"])`, so parameter names equal `model.language_model.*`.
  - `from_dir(folder, device="cpu")` loads the `model.language_model.*` tensors strictly and ignores the vision tower and the projector.
  - `logits(rows: list[Row]) -> list[list[np.ndarray]]` returns, for each row and each of its questions, the option scores: the max over each readout group of `h_slot @ embed_tokens.weight[group].T`.
  - `capture(rows, layers) -> list[list[dict]]` returns one dict per question with these keys:
    - `logits [k]`;
    - `head_inputs [k, d]`, the normed slot hidden state repeated once per option, so the backend's `[rows, k, d]` layout holds;
    - `option_rows [k, d]`, each option's best-form embedding row;
    - `hidden_mean [len(layers), d]` over the row's state tokens.
  - Batching sorts rows by length into chunks of at most `TOKEN_BUDGET` padded tokens, as `d1_omni/torch.py` does.
- `build_d1_lm(folder)` writes:
  - `config.json`, via `d1_lm_config(vocab)`: `model_type` `"lfm3_vl"`, `d1_attention` `"set"`, `d1_set_size` 16, `d1_codes` 2, `tie_word_embeddings` true, and a `text_config` with `model_type` `"lfm3"`, hidden 64, intermediate 128, 6 layers typed `["conv", "full_attention", "conv", "sliding_attention", "conv", "full_attention"]`, 4 heads, 2 kv heads, head_dim 16, `conv_L_cache` 7, `conv_bias` false, `sliding_window` 8, `use_sandwich_norm` true, `norm_eps` 1e-5, and `rope_parameters` for both attention types with partial factor 0.5 on `full_attention`;
  - `calibration.json`: `{"default": 1.337, "temperatures": {}}`;
  - the tokenizer files;
  - `model.safetensors`, with random weights (std 0.2 on matrices) plus an unused `model.vision_tower.dummy.weight`.
